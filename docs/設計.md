# 解剖学 3D単語帳 設計

このアプリの設計の正本。方針を変えたらここを直す。

## 目的と対象

- 対象は医療系の1年生（医・歯・薬・看護・PT/OT）。
- 初心者がつまずく3つを、1つのアプリで同時に練習できるようにする。
  1. 大量の専門用語の暗記
  2. その部位が体のどこにあるか
  3. 英語名の暗記
- 日本語の用語は日本解剖学会『解剖学用語 改訂13版』の表記に合わせる。英語名・ラテン名は Terminologia Anatomica 2nd ed.（TA2）が基準。

## 学習の仕組み

1つの語に4つの問い方を付け、それぞれ別々に FSRS で復習の間隔を決める（カードIDは `語ID:問い方`）。筋にはさらに3つ付く。

| 問い方 | ID | 内容 |
|---|---|---|
| 位置→名前 | `locate` | 3Dで光った部位の名前を4択で答える。選択肢は3Dで近くにある同じ系統の語 |
| 名前→位置 | `point` | 名前を見て3Dの上でタップする。より細かい語の部品をタップしても正解（脳→小脳） |
| 日→英 | `ja2en` | 最初は英語の4択。復習の段階で2回以上解いたらつづりの入力。1文字違いは「惜しい」 |
| 英→日 | `en2ja` | 英語の音声を聞いて日本語を4択で答える |
| 起始・停止 | `attach` | 筋だけ。「起始 → 停止」の4択。答えると筋を半透明にし、骨の上に起始（緑）・停止（紫）を示す |
| 支配神経 | `nerve` | 筋だけ。支配神経の4択 |
| 作用 | `action` | 筋だけ。おもな作用の4択 |

- 判定: 正解＝Good、惜しい＝Hard、不正解・わからない＝Again。
- 隠れた部位（`xray: true`）は、強調するとき周りを半透明にする。タップでは答えられないので `point` は出さない。
- 選択肢に、答えを含む語や答えに含まれる語は出さない（環椎の問題に頚椎を出さない）。
- 筋の3つの問い方は、その筋の「位置→名前」が復習の段階（State.Review）に入ってから出す。筋の場所を覚える前に起始・停止まで背負わせない。選択肢は3Dで近くの筋のもの（同じ文の選択肢は出さない）。
- 流れ: レッスン（3Dで1語ずつ見る → 確認テスト：タップと位置当てを交互に）→ 復習に入る。復習は期限の来たものを先に、新しい問い方は1日20まで。新しい問い方は先に学んだレッスンから順に出し、レッスンの中では問い方ごとに並べる（後から解禁される筋の問い方が、新しいレッスンの後ろに回り続けないように）。
- すべての語に、読み・漢字の意味・英語の語源・一言説明を付ける。語源は日本語と英語が同じ形を表していることを見せ、英語の暗記を楽にするため。

### BodyParts3D に無いもの（3Dで示せない）

末梢神経（坐骨神経・正中神経など）、脊髄の表面、肺の実質、甲状腺、耳下腺、S状結腸、外頚動脈、尾骨、広背筋・腹直筋・内腹斜筋・腹横筋・咬筋・側頭筋、顔の表情筋、女性生殖器（男性モデルのみ）、骨の突起・窩などの「部分」。

- 肺は気管支と血管の枝を包む凸包で外形を近似している（`shape: "hull"`）。説明文にも近似と書く。
- 盲腸は回盲部の部品で示す。
- 骨の部分（烏口突起など）はピンで示す（下の「骨の部位（ピン）」）。ただし頭蓋底の小さな孔（卵円孔・正円孔・棘孔・内耳孔など）と蝶形骨の小翼は、モデルが粗くて形が分からないので収録していない。肋軟骨は第1〜7しか無いので肋骨弓も示せない。
- 足りない筋・神経は Z-Anatomy（CC BY-SA 4.0、BodyParts3D 由来で座標がそろう）から足すのが候補。

## データの流れ

```
npm run fetch:sources   BodyParts3D 4.0 を data-raw/bp3d/ に取得（約600MB、git の対象外）
npm run build:models    content/terms/*.json の parts → 系統別 GLB と public/models/index.json
npm run build:wikidata  Wikidata の日本語名などを data-raw/wikidata.json に（照合用）
npm run build:audio     英語の発音 → public/audio/*.m4a と index.json（macOS の afconvert を使う）
npm run validate:content  内容の検査と docs/要確認用語.md の生成（npm run build の最初にも走る）
```

- GLB・音声のファイル名には中身のハッシュを付ける。PWA が CacheFirst で持っても古いものが残らない。
- 3D: mm・Z上 → m・Y上へ `(x, z, -y) × 0.001`。meshopt で簡略化（ratio 0.3・error 0.004）と圧縮。合計約11MB。
- 同じ名前・同じ外接箱の部品（is-a と part-of の木の重複）は1つにまとめる。
- 左右がある語は、カメラを寄せる先・ラベルの位置・「近くの語」の計算に右側（本人の右）の部品を使う。

## 内容ファイルの書き方（content/terms/<系統>.json）

```json
{ "system": "skeletal", "units": [ { "id": "skel-upper", "title": "上肢の骨", "terms": [
  { "id": "humerus", "ja": "上腕骨", "yomi": "じょうわんこつ", "en": "humerus", "enAlt": [], "la": "humerus",
    "parts": ["humerus"], "level": 1, "kanji": "…", "etym": "…", "note": "…" } ] } ] }
```

- `parts`: 部品の指定。
  - 部品名（BodyParts3D の英語名）。左右を外して比べるので `"humerus"` で左右両方。`*` が使える（`"* metacarpal bone"`）。
  - 指定に right / left が入っていれば左右込みで比べる（`"cavity of right atrium"`）。
  - `"FMA7309"` のような概念ID（is-a / part-of の表で部品に展開）。
  - `"!FJ2044"` はその部品を除く（元データで位置がずれている部品など）。
- `of`: 骨の部位（大結節など）のときの親の骨の語ID。`parts` を省くと親の骨の部品を使う。椎骨・肋骨の部位は代表の1個を `parts` で指定する（第3腰椎・第6肋骨など）。位置は content/pins.json のピン。
- `origin` / `insertion` / `nerve` / `action`: 筋の起始・停止・支配神経・作用（4つそろえる）。`originAt` / `insertionAt` は起始・停止の骨の部位の語ID（3Dで緑・紫のピンを示す）。神経は選択肢として比べるので、同じ神経は同じ書き方にする（ハムストリングはどれも「坐骨神経」）。
- `level`: 1＝必修、2＝基礎、3＝発展。
- `xray`: ほかの構造に隠れる部位。`color`: 系統の色と違う色（静脈の青など）。`shape: "hull"`: 凸包で形を示す。
- `check`: 表記を教科書で確かめてほしい語。docs/要確認用語.md に出る。確かめたら消す。
- 語を足したら `npm run build:models`（と `build:audio`）を実行する。しないと validate が止める。
- 発音の読み違いは content/pronunciation.json の単語辞書に発音記号を足す。

## 骨の部位（ピン）

BodyParts3D は骨を1つの形としてしか持たないので、突起・窩・稜などの「部位」は骨の表面の位置（ピン）で示す。

- 内容: content/terms/skeletal.json の `skel-pt-` で始まるレッスン（9レッスン・149部位＋隆椎）。部位は `of` で骨を指す。
- 位置: content/pins.json に `{ "部位の語ID": { "at": [[x, y, z], …], "r": 半径, "n": [外向き] } }`。座標はモデル座標（m・Y上・前が +z）で本人の右側（x < 0）。表示とタップの判定は左右を折り返して両側に効く。
  - `at` が1点なら結節・突起・孔など、数点なら稜・線・縫合（点の列）。孔（閉鎖孔・大後頭孔・椎孔など）は孔の中心に置き、球の範囲で縁をぐるりと示す。
  - `n` は面の外向き。その向きの面だけを塗り（肩甲骨のような薄い骨で裏まで塗らない）、カメラもその向きから寄る。外科頚・橈骨頚のように骨を一周する部位は `v`（カメラの向きだけ）にして全周を塗る。
- 表示: src/viewer.ts のスポット用材質（シェーダー）が、ピンの球の中の表面を色で塗り、縁を少し濃くする。部位を出すときは親の骨だけを不透明にして周りを半透明にする。
- 出題: 位置→名前の選択肢はピンが近い部位。名前→位置は骨だけを見せて正面やや右から映し、ピンの範囲（半径＋6mm）に当たれば正解。外れたらタップした所を青い点で示す。
- ピン打ちツール: `?admin=1` で開くと「ピン」タブが出る（#/admin）。部位を選んで骨をクリックすると位置が決まる（左側をクリックしても右側に記録）。「点を足す」で稜や縫合を数点で打つ。半径はスライダー。開発サーバーでは「保存」で content/pins.json を書きかえる（vite.config.ts の pinWriter）。それ以外ではファイルとして保存する。
- 最初の149部位のピンは、骨の形から規則で計算し、骨を描いた画像で1つずつ確かめた。1か所を直すときはピン打ちツールを使う。部位をまとめて足すときは規則で作る:
  - `scripts/pins/rules/*.mjs` に部位ごとの規則を書く。規則の種類: `ext`（ある向きに最も出た点。`box` で範囲を絞る）、`ridge`（断面ごとの最も出た点の列＝稜・縁）、`groove`（輪郭の溝の底と両わきの稜）、`notch`（縁の最も引っこんだ所）、`cap`（骨頭に球を当てはめた縁＝解剖頚）、`seam`（2つの骨が接する所＝縫合）、`slices`（高さ s の断面に横から当てる）、`ray` / `rays`（確認画像の枠の中の割合で当てる。`center` で孔の縁の平均＝孔の中心）、`between` / `towards` / `nearestTo` / `near` / `fromMid`。`ring: true` は骨を一周する部位（`v` で書く）。
  - `node scripts/pins/compute.mjs scripts/pins/rules/<骨>.mjs` で計算して data-raw/pin-check/ に確認画像（部位ごとに色と名前）を描く。合ったら `--write`（まだピンの無い部位だけ書く）。規則で作り直すときは `--force`（ピン打ちツールで直した分も上書きするので注意）。
  - 下見は `node scripts/pins/inspect.mjs view|hits|depth`（骨の画像、光線が当たる所の地図、奥行きの地図）。孔は hits で縁を探し、くぼみ（眼窩）は depth で探す。
  - 画像を目で見て座標を読むと少しずれやすい。決めたら必ず確認画像で確かめる。

## アプリの作り

基礎医学演習アプリ（/Users/hattoriyuusuke/アルゴリズム学習/問題演習アプリ）の型を引き継いだ別アプリ。Vite + TypeScript（フレームワークなし）+ three.js + ts-fsrs + Dexie + vite-plugin-pwa + zod + vitest。

| ファイル | 役割 |
|---|---|
| src/viewer.ts | three.js の表示。系統ごとの GLB 読み込み、タップ（外れたら周りを少しずつ探す）、強調・半透明・色分け、骨の部位のスポット、カメラ移動、ラベル |
| src/landmarks.ts | ピンの中心・広がり、タップした点との距離（左右の折り返し）、近い部位 |
| scripts/pins/ | ピンを規則で計算する道具（compute.mjs）と規則（rules/）、下見（inspect.mjs）、部品の読み込みと描画（geometry.mjs） |
| src/content.ts | 内容の読み込み（content/*.json を import）と models/index.json |
| src/study.ts | 出題順（期限→新規）、選択肢、覚え具合、入力式への切り替え |
| src/fsrs.ts | FSRS（基礎医学演習アプリと同じ設定）と記録 |
| src/answer.ts | 英語の答え合わせ |
| src/db.ts | Dexie（anatomy-study-v1）: schedules・reviewEvents・learned・settings |
| src/ui/*.ts | ホーム・レッスン・出題・復習・図鑑・進捗・クレジット・ピン打ちツール（admin.ts） |

| src/install.ts | ホーム画面に追加する案内（iOS は手順、Chrome はボタン） |

画面: ホーム（今日の復習とレッスン一覧）、レッスン、復習、図鑑（系統の切り替え・検索・タップで調べる・この部位だけ表示・骨の部位の一覧・筋の起始停止を骨で見る）、進捗（覚え具合で人体を色分け）。図鑑の一覧には骨の部位を出さず（長くなるので）、検索したときと骨を選んだときに出す。骨の部位の上をタップすると骨ではなく部位を選ぶ。

## 公開とスマホ

- 公開先は https://9hckg4shj6-glitch.github.io/anatomy-app/ （GitHub リポジトリ 9hckg4shj6-glitch/anatomy-app）。`main` に push すると `.github/workflows/pages.yml` が `npm run check` を通して GitHub Pages に出す。base（`/anatomy-app/`）は vite.config.ts が GITHUB_ACTIONS のときに付ける。
- PWA（vite-plugin-pwa）。HTML・JS・CSS・`models/index.json`・`audio/index.json` は最初に保存し、GLB と音声は開いたときに保存する（CacheFirst。ファイル名にハッシュがあるので古いものは残らない）。
- 新しい版: Service Worker が入れかわったら、ホームにいれば読み直し、レッスンや復習の途中ならホームに戻ったときに読み直す（レッスンの進み具合は最後まで保存しないため）。ホーム画面のアプリは開き直しても読み込み直さないことが多いので、画面に戻るたびに新しい版を確かめる（src/main.ts）。
- 記録は端末ごと（IndexedDB）。iOS は Safari とホーム画面のアプリで記録が別なので、ホームの案内で「追加してから始める」よう勧める。レッスンを終えたときに `navigator.storage.persist()` で消されにくくする。端末をまたぐ同期は Phase 3。
- スマホの画面: 3Dを上に留め、その下で説明がスクロールする。「次へ」「前へ」は画面の下に留める。系統のボタンは1行で横にすべらせる。横向き（高さ540px以下）と PC は3Dと説明を左右に並べる。ノッチ・ホームバーの分は `env(safe-area-inset-*)` であける。
- アイコン: `public/icons/icon.svg` が元。`npm run build:icons` で PNG（角丸・iOS 用の正方形・Android 用の maskable）を作る。

## 確認方法

- `npm run validate:content` と `npm run test`
- 公開した版は、スマホで公開先の URL を開き、ホーム画面に追加して確かめる（LAN の http では Service Worker が動かないので、オフラインと更新は公開先か `npm run preview` で見る）。
- `npm run dev` → PC とスマホ（同じ Wi-Fi で `http://<MacのIP>:5173/`）で、系統ごとの読み込み、タップで正しい構造が選ばれるか、レッスン→復習の記録、音声、2回目以降オフラインで動くかを見る。
- 骨の部位は、レッスンで1つずつ光る所が合っているか、名前→位置でタップした所が判定されるかを見る。ずれていたら `?admin=1` のピン打ちツールで直す。
