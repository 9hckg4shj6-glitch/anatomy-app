# 解剖学 3D単語帳 設計

このアプリの設計の正本。方針を変えたらここを直す。

## 目的と対象

- 対象は医療系の1年生（医・歯・薬・看護・PT/OT）。
- 初心者がつまずく3つを、1つのアプリで同時に練習できるようにする。
  1. 大量の専門用語の暗記
  2. その部位が体のどこにあるか
  3. 英語名の暗記
- 日本語の用語は日本解剖学会『解剖学用語 改訂13版』の表記に合わせる。英語名・ラテン名は Terminologia Anatomica 2nd ed.（TA2）が基準。

## 学習の仕組み

1つの語に4つの問い方を付け、それぞれ別々に FSRS で復習の間隔を決める（カードIDは `語ID:問い方`）。筋にはさらに3つ付く。

| 問い方 | ID | 内容 |
|---|---|---|
| 位置→名前 | `locate` | 3Dで光った部位の名前を4択で答える。選択肢は3Dで近くにある同じ系統の語 |
| 名前→位置 | `point` | 名前を見て3Dの上でタップする。より細かい語の部品をタップしても正解（脳→小脳） |
| 日→英 | `ja2en` | 最初は英語の4択。復習の段階で2回以上解いたらつづりの入力。1文字違いは「惜しい」 |
| 英→日 | `en2ja` | 英語の音声を聞いて日本語を4択で答える |
| 起始・停止 | `attach` | 筋だけ。「起始 → 停止」の4択。答えると筋を半透明にし、骨の上に起始（緑）・停止（紫）を示す |
| 支配神経 | `nerve` | 筋だけ。支配神経の4択 |
| 作用 | `action` | 筋だけ。おもな作用の4択 |
| 語根→意味 | `rootMeaning` | 語根カードだけ（語ID は `root:<語根ID>`）。語根と例の英語名を見て意味の4択 |
| 意味→語根 | `rootForm` | 語根カードだけ。意味と例の日本語名を見て語根の4択 |

- 判定: 正解＝Good、惜しい＝Hard、不正解・わからない＝Again。
- 隠れた部位（`xray: true`）は、強調するとき周りを半透明にする。タップでは答えられないので `point` は出さない。
- ほかの構造をおおったりふさいだりする形（`veil: true`。xray と一緒に付ける）は、ふだんはごく薄く見せてタップでは選べず、強調したときだけ不透明にする。小腸の前に垂れる大網、空間の形である口腔・鼻腔、舌の上をおおう軟口蓋・口蓋垂、舌の中のオトガイ舌筋（小腸や舌をタップで答えられるように）。系統だけを6方向から描いて語ごとに映るピクセルを数え、ほとんど映らない語は xray、ほかの語をふさぐ語は veil にした。
- 選択肢に、答えを含む語や答えに含まれる語は出さない（環椎の問題に頚椎を出さない）。骨・器官の部位では、同じ骨の上でピンの範囲が入れ子になる部位（椎弓と椎弓根、寛骨臼と月状面、腸骨と腸骨稜）を出さない（src/landmarks.ts の nestedLandmarks。一方の点がすべて、または点の中心が相手の半径の8割以内）。関節で向かい合う別の骨の部位（大腿骨頭と寛骨臼）と、薄い骨の表と裏（棘下窩と肩甲下窩。面の向き n が逆）は紛らわしい選択肢として残す。
- 筋の3つの問い方は、その筋の「位置→名前」が復習の段階（State.Review）に入ってから出す。筋の場所を覚える前に起始・停止まで背負わせない。選択肢は3Dで近くの筋のもの（同じ文の選択肢は出さない）。喉頭・咽頭・舌・骨盤底の筋は呼吸器・消化器・泌尿器の語なので、筋の問い方の選択肢は系統をまたいで3Dで近い筋から選ぶ。
- 流れ: レッスン（3Dで1語ずつ見る → 確認テスト：タップと位置当てを交互に）→ 復習に入る。復習は期限の来たものを先に、新しい問い方は1日20まで。新しい問い方は先に学んだレッスンから順に出し、レッスンの中では問い方ごとに並べる（後から解禁される筋の問い方が、新しいレッスンの後ろに回り続けないように）。
- すべての語に、読み・漢字の意味・英語の語源・一言説明を付ける。語源は日本語と英語が同じ形を表していることを見せ、英語の暗記を楽にするため。
- 基本の用語（方向・面・運動。下の「基本の用語」）は3Dの部品を持たず、図（矢印・面・骨を動かす）で示す。問い方は位置→名前（図→名前）・日→英・英→日の3つ。
- 説明・作用の文の中の基本の用語（「外転」「内側」など2文字以上）は点線で示し、タップで意味を出す（src/ui/term-card.ts）。図鑑では「3Dで見る」でその用語の図へ移る。
- 演習（#/drill、src/ui/drill.ts）: 系統・問い方・数を選び、レッスンで学んだ語から解く。「苦手な順」は思い出せる確率の低い・忘れた回数の多い問い方から（一度は解いたものだけ）。1周ごとに1つの語から1問ずつ取る（study.ts の practiceQueue）。答えは `source: "practice"` で記録し、次の出題日にも反映する（1日の新規上限には数えない）。
- 記録の書き出し・読み込み（進捗の画面、src/backup.ts）: 4つの表を JSON に書き出す。読み込みは上書きせず足し合わせる（同じカードは最後に解いたのが新しい方、履歴は ID で重ねない、学んだ日時は早い方）。端末をまたぐ同期の代わり。
- 押しまちがいの取り消し: 正解でなかった答えの下に「押しまちがえた（取り消して解き直す）」を出す。押すと、その1回の解いた記録を消して覚え具合を解く前に戻し（fsrs.ts の recordReview が返す undo）、同じ問題をもう一度出す。タップで答える問題や4択でのうっかりで、間隔が短くならないように。
- 設定（進捗の画面、src/settings.ts。db.settings に1つずつ保存）: 英語の発音を自動で鳴らすか（レッスン・図鑑・答え合わせ・英→日の問題。🔊はいつでも鳴る）、1日に新しく始める問い方の数（10・20・30・40。初めは20）。

## 語根カード

英語名は意味のある部品（語根）の組み合わせなので、語根を覚えると初めて見る名前も意味が分かる（brachi-「腕」→ brachial artery・brachialis・brachioradialis）。content/roots.json に6グループ138個（体の部位・骨の名前・器官と組織・位置と方向・形と大きさと数・動きとはたらき）。

- 語根ごとに `match`（例の語を英語名 en・enAlt から拾う正規表現。`la: true` ならラテン語名も見る）・意味・由来・覚え方。例の語は書かずに自動で拾う（src/roots.ts の examplesOf）。誤って拾う語（posterior の oste、maxillary の axill、lung の lun、scarpa の carp、anastomosis の nas）は match で除き、tests/roots.test.ts で確かめる。例の語が1つも無い語根は validate が止める。
- レッスン（#/roots/<ID>）は1グループを11個までに分ける。語根を1つずつ見せ（例の語を3Dで光らせる）→ 語根→意味の確認テスト → 復習に入る（learned に `root:<ID>`）。復習では語と同じ列に入る（review.ts の askItem で出し分け）。
- 語の中身（term-card）には、英語名に含まれる語根を例の少ない（特徴のある）順に3つまで出し、タップで意味を出す。#/roots は一覧。

## 図鑑の「関係する語」と断面

- 関係する語（src/related.ts）: 筋→支配神経（支配神経の文に神経の語の日本語名が入っているか）、神経→支配する筋（「まとめて3Dで見る」で筋を橙、神経を黄で示す）、骨→そこから起こる筋・停止する筋（付着面の骨の語ID と、originAt・insertionAt の骨の部位の親）、骨の部位→そこから起こる筋・停止する筋。#/explore/<語ID> で語を選んで開ける（演習のまちがえた語・語根の例から）。
- 断面（「断面」ボタン）: renderer の clippingPlanes で全身を1つの面で切る。切った所から見える形の裏側を組織の色で平らに塗って切り口にする（viewer.ts の SURF_SECTION。断面のときだけ材質を両面にする）。タップは切り取った側に当たったものを除くので、切り口をタップするとその構造を選べる。水平断・矢状断・前頭断とつまみで位置、「反対側を残す」。水平断は上側を残して下から見る（CT と同じ向き：前が上、本人の右が画面の左）。語を選んでいればそのまわりに寄る。脊髄の伝導路のような中に埋もれた語は、断面で見るのがいちばん分かりやすい。
- CT の画像（TotalSegmentator）を使う断面は、この3Dの断面で代わりにした。

### BodyParts3D に無いもの

BodyParts3D に無い次の構造は、Z-Anatomy から骨に合わせて取り込んだ（下の「Z-Anatomy の取り込み」）。
広背筋・腹直筋・内腹斜筋・腹横筋・腰方形筋、表情筋、咀嚼筋（側頭筋・咬筋・翼突筋）、脊髄・馬尾・交感神経幹、末梢神経（腕神経叢とその枝・肋間神経・下肢の神経）、脳神経（Ⅰ・Ⅲ・Ⅴの枝・Ⅵ〜Ⅻ）、甲状腺（錐体葉つき）・上皮小体・耳下腺、肺（葉ごとの形）、
口腔・軟口蓋・口蓋垂・咽頭（鼻部・口部・喉頭部）、耳下腺管・顎下腺管、鼻腔・前頭洞・蝶形骨洞・篩骨蜂巣、大網・小網、副膵管、腎盤、射精管、腺下垂体・神経下垂体（下垂体はこの2つで示す。BodyParts3D の下垂体とほぼ同じ形で重なるため）、
動脈の枝（外頚動脈・顔面動脈・浅側頭動脈・顎動脈・後頭動脈、肋間動脈、左胃動脈・胃十二指腸動脈・左結腸動脈、浅掌動脈弓、上殿・下殿・閉鎖・内陰部動脈、大腿深動脈・腓骨動脈）、外頚静脈、総頚動脈・内頚静脈の上の部分（BodyParts3D は頚の下の方で終わっている）。

BodyParts3D で1つの形になっている尾骨（仙骨に含まれる）・S状結腸（下行結腸に含まれる）・総胆管（総肝管に含まれる）・方形葉（肝臓の第IV区域に含まれる）と、Z-Anatomy で咽頭口部と1つになっている口腔は、形を平面で分けて示す（下の「形を平面で分ける」）。

BodyParts3D の部品のうち名前の末尾が M のもの（FJ1449M など）は左右を反転した写しで、骨盤底の筋（尾骨筋・肛門挙筋の3部・外肛門括約筋）では左側が二重になる。`"!FJ1449M"` のように除く。

まだ示せないもの:

- 中硬膜動脈: Z-Anatomy の形が頭蓋の外の短い部分だけで、頭蓋の内面を走る様子が分からない。
- 女性生殖器（どちらも男性モデルのみ）。
- 上顎洞（どちらにも無い。前頭洞などの説明に書いた）。
- 胸膜（Z-Anatomy の形は肺の表面とほぼ同じで、肺と見分けられない）。腹膜そのもの。
- 横行結腸間膜・S状結腸間膜（BodyParts3D の横行結腸間膜は腸の後ろの大きな幕のような形、Z-Anatomy の結腸間膜は小さな切れ端で、どちらも使えない）。
- 葉気管支（Z-Anatomy の形が BodyParts3D の主気管支と重なる）。肺区域（区域気管支の形だけがある。区域気管支はまとめて1語）。
- 骨の部分（烏口突起など）はピンで示す（下の「骨の部位（ピン）」）。ただし頭蓋底の小さな孔（卵円孔・正円孔・棘孔・内耳孔など）と蝶形骨の小翼は、モデルが粗くて形が分からないので収録していない。肋軟骨は第1〜7しか無いので肋骨弓も示せない。
- 盲腸は回盲部の部品で示す。
- 胸管・乳び槽・リンパ管（どちらにも無い。リンパ系はリンパ節と扁桃で示し、レッスンの intro に流れを書いた）。半規管（Z-Anatomy の内耳は蝸牛と前庭だけ）。横隔神経・反回神経（Z-Anatomy の迷走神経は1つの形で、横隔神経は無い）。
- 大脳の溝（中心溝など）と楔部・舌状回などの細かい区分: Z-Anatomy の形は BodyParts3D の大脳（回・葉）と重なってちらつくので形としては使わず、ピンで示す（下の「頭頚部と体幹（Phase 3 その6）」）。小脳の部位（虫部・扁桃など）は同じ理由で見送り。
- 頚神経叢の枝（小後頭神経・大耳介神経など）・横隔神経・後頭下神経・心膜（どちらにも無い）。頭蓋底の孔は上のとおりモデルが粗く、頭蓋窩の説明に書いた。

## 関節・靱帯とリンパ系（Phase 3 その3）

- 関節・靱帯（系統 `joints`、色 #b7c7cc、content/terms/joints.json）: Z-Anatomy の Joints100 から、肩・肘・手首（15）、股関節と膝関節（17）、足首と足（10）、脊柱と胸郭（11）、骨盤と顎関節（14）の5レッスン67語。前腕骨間膜・下腿骨間膜・長足底靱帯・茎突舌骨靱帯・椎間円板は BodyParts3D。
  - 関節（肩関節など）は関節包の形で示す。関節包は中の靱帯・関節唇・半月をおおうので veil（ふだん薄く、強調したときだけ不透明）。
  - 出題の画面では骨を少し濃く（0.34）添える（sceneFor の contextOpacity）。どの骨をつなぐかが分かるように。
  - 靱帯は形の主軸の向きに線維を描く（build-models.mjs の fibers。関節包・関節円板・半月・関節唇・髄核・恥骨結合は除く）。半月・関節円板などの線維軟骨は軟骨の色（CARTILAGE）。表示の質感は TISSUES.ligament。
  - 胸椎の椎間円板は、胸椎の語（FMA の概念）に含まれて骨格の GLB に入っている。強調では正しく出るが、関節の画面では骨格が添えるだけなのでタップでは選べない（頚・腰の椎間円板で答えられる）。
- リンパ系（系統 `lymphatic`、色 #8dbb52、content/terms/lymphatic.json）: Z-Anatomy の LymphoidOrgans100 から、口蓋扁桃とリンパ節の群（頭頚部・胸部と上肢・腹部と骨盤と下肢）の3レッスン29語。部位ごとに分かれた小さな群をまとめて1語にした（腋窩リンパ節＝5群など）。BodyParts3D の形が無い系統なので、GLB は `lymphatic-za.<ハッシュ>.glb` だけ（build-models.mjs は Z-Anatomy だけの系統もそのファイルを系統の GLB にする）。
- 筋膜・支帯と滑液包（筋系の mus-fascia）: 屈筋支帯・腸脛靱帯・白線・鼡径靱帯など。色は #d6cdb8（筋膜。靱帯の質感・線維あり）と #9fc2da（滑液包。内臓の質感・線維なし）で、viewer.ts の SHEET・BURSA と build-models.mjs の BURSA で見分ける。大腿筋膜・胸腰筋膜は筋を広くおおうので veil。
- 隠れた語（xray）は `node scripts/visibility.mjs <系統>` で決めた: 出題と同じくその系統だけを不透明に描き（veil の語は除く）、6方向から部品の番号で塗った画像で、語ごとに「見えている画素 ÷ その語だけを描いた画素」の最大を出す。8%未満なら xray、35%を超えるのに xray なら外す（`--all` で全部の語）。関節・リンパの系統は骨が半透明なので、深い靱帯やリンパ節でも見えていれば xray にしない。

## 下肢（Phase 3 その4）: 局所解剖と筋の動き

下肢を優先して、知識（骨の部位21・筋15・関節と靱帯12・神経9・血管22）と、新しい系統「局所解剖」21語、筋の作用を骨の動きで見る機能を足した。

- 骨の部位（content/pins.json、規則は scripts/pins/rules/lower.mjs）: 腸骨・坐骨・恥骨は寛骨の上の広い範囲なので、大きな球を十数個並べたピンで示す（`ring` で内面も塗る。内側から見たときの塗り残しは med の光線を足して埋めた）。恥骨上枝・下枝・坐骨枝は `inset` で点を骨の中へ寄せ、両面を塗る。ほかに転子窩・恥骨筋線・膝窩面・脛骨の内側面・鵞足・腓骨切痕・距骨頚・距骨後突起・腓骨筋滑車・足根洞・長腓骨筋腱溝・第1中足骨粗面・中足骨頭（5点）・果溝（脛骨・腓骨。腱が回る滑車で、筋の動きの帯もここを通す）。
  - スポットの塗り（viewer.ts の USE_SPOTS）は、いちばん内側に入っている球の色と縁で塗る（球を並べた範囲で、重なった所に縁の線が出ないように）。

### 局所解剖（系統 `regional`、content/terms/regional.json）

大腿三角・内転筋管・内転筋腱裂孔・筋裂孔・血管裂孔・閉鎖管、大坐骨孔・小坐骨孔・梨状筋上孔・梨状筋下孔・膝窩・足根管、大腿と下腿の区画6つ、足弓3つ（4レッスン21語）。部品を持たず、ほかの語を組み合わせて示す（語の `region`）。

- `region.bounds`（境界）はオレンジ、`contents`（通るもの）はその語のもとの色（神経の黄・動脈の赤・静脈の青・筋の赤）。境界の筋・靱帯は半透明（中の神経・血管が透けて見える）、骨と骨の部位は不透明・スポット。ほかの語は隠し、骨格は薄く添える。右側で示すので左側の形も隠す（内側から見るとき反対側の脚がじゃまにならないように）。
- `outline` は囲みの線（橙の管＋ごく薄い塗り。奥行きを無視して手前に描く）。`open` なら閉じない（足弓のアーチ）。座標は形とピンから求めた（縫工筋と長内転筋が前から見て重なる所＝大腿三角の先、靱帯の主軸の両端など）。
- `section` があると、見せるとき体をその面で切る（図鑑の断面と同じ clippingPlanes。図鑑で断面を使っているときはそちらが優先）。区画は水平断で下から見る（CT の向き）。断面では区画の外の筋をくすんだ色（MUTED）で不透明に描き、細い神経・血管は隠して、CT のような切り口にする。境界（筋間中隔）は不透明の橙の線になる。
- `view` はカメラ（基本の用語の図と同じ）、`prompt` は位置→名前の問題文、`boundsLabel` / `contentsLabel` は説明の見出し（足弓は「つくる骨」「支えるもの」）。
- 出題: 位置→名前（同じレッスンの語から4択）と日→英・英→日。タップはできないので名前→位置は出さない（`isDrawn`）。選んだ語を青で示さない。
- 語の説明に境界と通るものの一覧（図鑑ではタップでその語へ）。図鑑の「関係する語」に「この語が出てくる局所」（大腿動脈→大腿三角・内転筋管など）。図鑑の系統のボタンに「局所解剖」（3Dの部品は無いので、語を選ぶと境界と通るものの系統を読み込む）。
- レッスンと出題の場面は sceneFor("regional", レッスンID) が、レッスンの語の境界・通るものの系統を読み込む。

- カメラは、いちばん大きく動く関節の軸の向きから（回す面が正面に見える）。体の右側・前から見るよう向きをそろえ、軸が縦（股関節の回旋）なら前の右上から。

- まとめた語と1本ずつの語は部品が重なるので、選択肢には互いに出ない（今までの「答えを含む語」の規則）。タップした部品は一番細かい語で答えるので、図鑑で肋骨をタップすると「第6肋骨」などと出る。
- 近くの語（index.json の neighbors。4択の選択肢の候補）は、部品の重なる語を除いてから近い順に8つ選ぶ（build-models.mjs）。除かないと、まとめた語（肋骨）の近くが1本ずつの語で埋まり、選択肢が系統の中から無作為になる。

- 見送ったもの: 肝臓の区域 S1〜S8（解剖学用語の名前「左外側後区域」などと臨床の呼び方が違う。S1＝尾状葉・S4＝内側区域は前からある）、肋軟骨の1本ずつ、大動脈弁・肺動脈弁の半月弁（BodyParts3D の名前が古い呼び方）、乳頭筋の1つずつ（左心室の後乳頭筋が無い）、脊髄神経の1本ずつ（Z-Anatomy でも1つの形）。

## 基本の用語（方向・面・運動）

筋の作用（肩関節の外転）や説明（内側上顆）は方向・運動の用語で書かれているので、初めに学べるようにした。content/terms/basics.json（系統 `basics`、ホームの一番上）。

- レッスン: 方向の用語10（上・下・前・後・内側・外側・近位・遠位・浅・深）、体の面4（正中矢状面・矢状面・前頭面・水平面）、運動の用語7（屈曲・伸展・外転・内転・外旋・内旋・回旋）、運動の用語10（回内・回外・背屈・底屈・内反・外反・挙上・下制・橈屈・尺屈）。
- レッスンの `intro`（段落の配列）は、レッスンの初めに1枚の説明として見せる（解剖学的正位、左右は本人から見た左右など）。どの系統のレッスンにも書ける。
- 1文字の語（上・浅など）は文の中の自動リンクにしない（上腕・浅層に紛れるため）。頭側・尾側・腹側・背側は、上・下・前・後の説明に書いた（同じ図になり、4択で両方正しくなるため）。
- `figure`: 図。座標はモデル座標（m・Y上・前が +z、本人の右が -x）。
  - `arrows`: 矢印 `[始点, 終点]` の配列。体の中を通っても見えるよう奥行きを無視して描く。太さは `view.size` に合わせる。
  - `plane`: 答えの面 `{ axis: "x"|"y"|"z", at }`（x＝矢状面、z＝前頭面、y＝水平面）。`guide` は目安に薄く出す面（内側・外側の正中面）。
  - `motion`: 関節の動き `{ from, to }`（関節ID → 角度°）。from の姿勢（無ければ解剖学的正位）から to へ動かし、止まってから初めに戻るのをくり返す（3.4秒）。動く骨はオレンジ、いちばん大きく動く骨の通り道を青緑の曲がった矢印で示し、皮膚は消す。肘を曲げたまま肩を回す（外旋）ような組み合わせも書ける。
  - `view`: カメラ `{ target, from, size }`（見る中心・カメラを置く向き・映す半分の高さ m）。縦長の画面では横も入るように引く。
  - 方向・面の図では皮膚を少し濃くする（浅・深の境が分かるように）。
- `foils`: 図→名前の4択に出してよい語。図に当てはまる別の語を出さない（近位の矢印は上も向くので「上」を出さない、正中矢状面に「矢状面」、外旋に「回旋」、内反に「回外」を出さない）。日→英・英→日の4択は同じレッスンの語から選ぶ。
- 関節: content/joints.json（`node scripts/joints.mjs` が骨の形とピンから作る）。関節ごとに動かす骨（語ID）・回す中心 `pivot`・回す軸 `axis`（右側。正の角度で `plus` の運動）。左右のある骨は右側の部品だけを動かす。`mid`（環軸関節）は正中の骨をすべて動かす。`slide` は回さずに axis の向きへ mm 動かす（肩甲骨の挙上は、鎖骨を胸鎖関節で回し、肩甲骨と腕を同じだけ上げる。回すと腕が横へ振れるため）。
  - 肩・股関節の中心は上腕骨頭・大腿骨頭に球を当てはめて求める（半径 20.8mm・22.9mm）。肘は上腕骨小頭と滑車のピン、前腕は橈骨頭と尺骨頭のピン、膝は大腿骨の両上顆、足関節は内果と外果のピンから。
  - 距骨下関節の軸は本当（約40°上向き）より足の長軸に近づけている（本当の軸で回すと前足が内へ振れる動きが目立ち、足の裏が内を向くのが分かりにくい）。
  - 並びは体の中心から先へ。1つの部品に複数の関節が効くときは、先の関節から順に回してから根元の関節で回す（src/viewer.ts の poseMatrix）。
  - 向きは tests/joints.test.ts で確かめる（正の角度で肘の屈曲なら手が前へ、など）。関節を足したら表と試験に足す。
- 図を足したら、開発サーバーで図鑑の検索から語を選び、動きの初めと終わりを見る。

## データの流れ

```
npm run fetch:sources   BodyParts3D 4.0 を data-raw/bp3d/、3.0 の細かい形を data-raw/bp3d-v3/、Z-Anatomy の FBX を data-raw/z-anatomy/ に取得（約3GB、git の対象外）
npm run build:models    content/terms/*.json の parts → 系統別 GLB（Z-Anatomy の分は <系統>-za）と public/models/index.json。
                        3.0 の形の重ね合わせ（初回だけ約5分、data-raw/bp3d-v3/aligned/ に覚える）とくぼみの暗さの計算で、全体で20分ほどかかる
npm run build:attachments  Z-Anatomy の付着面 → 筋の起始・停止の面 public/models/attachments-za.json
node scripts/build-models.mjs --attached-bones  付着面・ピンが乗っている1本ずつの骨 → index.json の attachedBones（build:models の最後にも走る）
npm run build:wikidata  Wikidata の日本語名などを data-raw/wikidata.json に（照合用）
npm run build:audio     英語の発音 → public/audio/*.m4a と index.json（macOS の afconvert を使う。基本の用語も含む）
node scripts/joints.mjs 基本の用語で骨を動かす関節 → content/joints.json
npm run validate:content  内容の検査と docs/要確認用語.md の生成（npm run build の最初にも走る）
node scripts/visibility.mjs <系統>  隠れて見えない語（xray を付けるかの目安）
```

- GLB・音声のファイル名には中身のハッシュを付ける。PWA が CacheFirst で持っても古いものが残らない。
- 3D: mm・Z上 → m・Y上へ `(x, z, -y) × 0.001`。meshopt で簡略化（許すずれを系統ごとに決める。下の「3Dの見た目」）と圧縮。合計約17MB（約200万面。骨3.5MB・筋4.6MB）。
- 同じ名前・同じ外接箱の部品（is-a と part-of の木の重複）は1つにまとめる。
- 部品の形は build-models.mjs の `readElements()` が返す `readMesh` で読む（下の CUTS で分けた形もこれで読める）。scripts/pins/ と scripts/za/ も同じものを使う。
- 左右がある語は、カメラを寄せる先・ラベルの位置・「近くの語」の計算に右側（本人の右）の部品を使う。

## 3Dの見た目

教科書のアトラスのアプリのように、形の細かさ・くぼみの陰・組織の質感が分かるようにした。

- 形の細かさ（scripts/hires.mjs）: BodyParts3D 4.0 はポリゴンを99%減らした版しか配られていない（上腕骨で約3,800面）。3.0 には95%減らした版（約5倍細かい）があるので、それを 4.0 の形に重ねて表示に使う。4.0 では骨格が手直しされ（頭蓋は約5.6%大きく、大腿骨・脛骨は長く、位置も動いた）、そのままでは重ならないので、相似変換（scripts/za/warp.mjs の icp）のあと、広がり 40→2.5mm のなめらかな変形で 4.0 の面へ寄せる。重ねたあとのずれ（4.0 の頂点→3.0 の面、3.0 の頂点→4.0 の面）の95%点と最大が LIMIT 以内のものだけを使う。骨は237部品のうち224、脳60、筋54（筋の多くは 4.0 で形が作り直されていて、3.0 の筋は細長い三角形が多く見た目も良くならない）。ファイル名は 4.0 の OBJ の Concept ID（FMA）。
  - 位置・大きさ・近さ（index.json）・ピン・付着面・Z-Anatomy の合わせ込みは今までどおり 4.0 の形で決める。3.0 の形は見た目だけ。
  - 切って分ける部品（CUTS）は、3.0 の形を同じ平面で切る。
- 簡略化（scripts/surface.mjs の simplify）: 許すずれを長さで決める（骨・脳 0.12mm、筋 0.4mm、ほか 0.1mm）。凹凸の多い骨には三角形が多く残り、なめらかな内臓・血管は少なくなる。
- 3.0 の形の無い筋（4.0 の粗い形のまま）は、三角形の角のでこぼこを Taubin の方法でならしてから減らす（relax。見た目がなめらかになり、三角形も約2割減る）。
- 骨格の中の軟骨（肋軟骨・椎間円板）は GLB の部品に `extras: { cartilage: true }` を付け、アプリで青みのある白（CARTILAGE）とつやで描く。
- 圧縮は meshopt の high（法線などに filter を使う）。量子化は位置14bit・法線10bit・AO と線維 8bit。
- くぼみの暗さ（AO。bakeAo）: 頂点から法線の側へ32本の光線を飛ばし、同じ GLB の形（Z-Anatomy の GLB では同じ系統の BodyParts3D の形も）にさえぎられる度合いを `_AO` に入れる。届く距離は系統ごと（AO_DISTANCE、骨 2.5cm・筋 2cm・内臓 4cm）。形の中から裏に当たったときは数えない（心臓の内腔のように中に入った形が真っ黒にならないように）。ほかの系統はさえぎらない（筋を消しても骨が暗く残らないように）。
- 線維の向き（muscleFibers・nerveFibers）: 筋は頂点ごとに、近い起始の点（付着面・無ければ骨の部位のピン）から近い停止の点への向き（扇形の筋では停止へ集まる）。起始・停止の無い筋は形の主軸、片方だけの筋（横隔膜など）はもう片方を形の中心とする。神経は頂点の周り5mmの点の並びの主軸で、管のように一方向へ長い所ほど強い（長さ＝強さ）。`_FIBER` に入れる。左側の筋は点を折り返し、正中をまたぐ筋は両側の点を使う。
- 表示（src/viewer.ts）: 背景は暗い色（骨・筋・陰がはっきり見える）。光はカメラに付けた3つ（左上の主な光・右の弱い光・後ろからの縁の光）と半球の光、部屋の映り込み（RoomEnvironment）。色は NeutralToneMapping。
  - 表面の材質（surface）は MeshPhysicalMaterial に、AO・細かい凹凸・色むら・線維を足すシェーダー（SURFACE_VERTEX / SURFACE_FRAGMENT）。組織ごとの値は TISSUES（骨・筋・神経・血管・内臓。系統と、線維の有無・筋の色で決める）。
  - 凹凸と色むらは、起動時に作る64³のつなぎ目の無いノイズ（3Dテクスチャ）を形の座標で引く。線維は、向きに沿って並べた6点のノイズの平均（線積分）で、向きにそろった細い筋（1mm）と束（4mm）を描く。法線は高さの画面上の変化から傾ける（Mikkelsen の方法）。遠くでは mipmap で自然に消える。
  - 骨の部位のスポットも同じ材質（USE_SPOTS）。半透明（周りを薄くするとき）は今までどおりの簡単な材質。
- 本体から離れた数枚の三角形（右の角膜・強膜・脈絡膜の中にある左眼の位置のかけら、肋間筋・手の骨間筋などの小さなかけら）は、OBJ を読むときに除く（surface.mjs の dropStrays。40枚以下・本体の2%未満・本体の外接箱から1cm以上）。見た目には映らないが、語の中心と大きさを狂わせていた（角膜の中心が両眼の間になり、寄る先とラベルがずれた）。

### 目と口

「目と口はリアリティが足りず学習しにくい」という声を受けて、形の粗さと、どの構造も系統の色1色（眼は紫・口は橙）だったのを直した。

- 語の `tissue`（質感）と `color`（もとの色）: 角膜・水晶体・硝子体・毛様体小帯は透明（clear）、強膜は白くなめらか（sclera）、虹彩は茶色で瞳孔から放射状のすじ（iris）、脈絡膜・毛様体はこげ茶、網膜は橙（retina）、外眼筋と上眼瞼挙筋は筋の赤、瞼板・総腱輪は白い密な線維（ligament）、涙腺は小葉の凹凸（gland）、涙嚢・涙小管・鼻涙管は粘膜（mucosa）。歯はエナメルのつや（tooth）、口唇・歯肉・軟口蓋・口蓋垂は湿った粘膜、舌は舌乳頭のざらつき（tongue）、唾液腺は小葉の凹凸、導管は白っぽく。
- 透明な組織（viewer.ts の SURF_CLEAR）: 地の色をほとんど散らさず、映り込み・つやの明るい所ほど濃く見せる（ガラスのように。角膜ごしに虹彩が見える）。強調・進捗の色のときは不透明（色が見えるように）。
- 網膜（SURF_INSIDE）: もとの色で断面でないときは暗く描く。眼球の中は光が届かないので、瞳孔の奥が黒く見える（網膜は厚みのある殻で、瞳孔から見えるのは内側の面。外側の面は脈絡膜・強膜に隠れる）。断面では網膜の色で描く。
- 虹彩のすじ（surface.mjs の radialFibers）: 形の中心から外への向きを `_FIBER` に入れ、瞳孔の縁の近くは弱くする。シェーダーの線維を細くする（fiberScale 0.35）。
- 粗い形の細分（surface.mjs の subdivide、build-models.mjs の SMOOTH）: BodyParts3D 4.0 の舌（524面）・口唇・顎下腺・舌下腺と Z-Anatomy の瞼板は角張っていて、3.0 の細かい形も無いので、表示の前に Loop の細分を2回かける。Loop の細分は粗い形ほど縮む（舌で平均0.5mm）ので、元の点を元の位置へ戻し、そのずれを間の点へならして配る（細分した形は元の点を通る）。位置・大きさ・近さは今までどおり細分前の形で決める。
- まだ無いもの: まぶた（眼瞼の皮膚・結膜）は BodyParts3D にも Z-Anatomy にも無いので、瞼板と眼輪筋で示す。耳（外耳・中耳・内耳）は系統の紫のまま。

- 確認: 開発サーバーで、骨（頭蓋の正面・肩）、筋（胸）、内臓（肝臓のまわり）、眼（正面と斜め前から角膜ごしの虹彩・瞳孔）、口（歯・歯肉・舌）を寄って見る。形を足したら、build:models のあとで data-raw/bp3d-v3/aligned/index.json（部品ごとのずれ back・there、mm）も見る。

## 内容ファイルの書き方（content/terms/<系統>.json）

```json
{ "system": "skeletal", "units": [ { "id": "skel-upper", "title": "上肢の骨", "terms": [
  { "id": "humerus", "ja": "上腕骨", "yomi": "じょうわんこつ", "en": "humerus", "enAlt": [], "la": "humerus",
    "parts": ["humerus"], "level": 1, "kanji": "…", "etym": "…", "note": "…" } ] } ] }
```

- `parts`: 部品の指定。
  - 部品名（BodyParts3D の英語名）。左右を外して比べるので `"humerus"` で左右両方。`*` が使える（`"* metacarpal bone"`）。
  - 指定に right / left が入っていれば左右込みで比べる（`"cavity of right atrium"`）。
  - `"FMA7309"` のような概念ID（is-a / part-of の表で部品に展開）。
  - `"!FJ2044"` はその部品を除く（元データで位置がずれている部品など）。
  - `"za:latissimus dorsi muscle"` は Z-Anatomy の形（名前は小文字・空白区切り、左右の扱いは同じ）。BodyParts3D の指定と混ぜてよい。
- `of`: 骨・器官の部位（大結節・噴門・肺門など）のときの親の骨・器官の語ID。`parts` を省くと親の部品を使う。椎骨・肋骨の部位は代表の1個を `parts` で指定する（第3腰椎・第6肋骨など）。肺門は右肺だけを `parts` にする（左肺が半透明になり、内側から右肺の内側面を見られる）。位置は content/pins.json のピン。
- `origin` / `insertion` / `nerve` / `action`: 筋の起始・停止・支配神経・作用（4つそろえる）。`originAt` / `insertionAt` は起始・停止の骨の部位の語ID（3Dで緑・紫のピンを示す）。神経は選択肢として比べるので、同じ神経は同じ書き方にする（ハムストリングはどれも「坐骨神経」）。
- `level`: 1＝必修、2＝基礎、3＝発展。
- `xray`: ほかの構造に隠れる部位。`veil`: ほかの構造をおおったりふさいだりする形（大網・口腔・鼻腔など）。xray と一緒に付ける。`color`: 系統の色と違う色（静脈の青、内臓の系統にある筋の赤 `#c75b4f` など）。`tissue`: 質感（clear・sclera・iris・retina・tooth・mucosa・tongue・gland・ligament。上の「目と口」）。無ければ系統から決める。
- `check`: 表記を教科書で確かめてほしい語。docs/要確認用語.md に出る。確かめたら消す。
- `motion`: 筋の作用の動き（上の「筋の作用を骨の動きで見る」。`view: "back"` で後ろから見る）。`from`: 語に寄るときにカメラを置く向き（無ければ今の向きのまま。胸椎など前から陰になる語）。`region`: 局所解剖の語（上の「局所解剖」。parts・of・figure の代わり）。
- 語を足したら `npm run build:models`（と `build:audio`）を実行する。しないと validate が止める。
- 発音の読み違いは content/pronunciation.json の単語辞書に発音記号を足す。

## 形を平面で分ける（CUTS）

BodyParts3D の仙骨は尾骨まで、下行結腸は S状結腸まで1つの形になっている。build-models.mjs の `CUTS` に「部品名・平面・下側の名前」を書くと、平面の下側を別の部品 `<ID>-<slug>`（名前は `Coccyx` など）にし、上側は元のIDのまま残す。三角形は切り口で割り、切り口は扇形でふさぐ。

- 仙骨: 横幅が最も細くなる高さ（y = 0.818 m）。その下が尾骨（`parts: ["coccyx"]`）。
- 下行結腸: 左腸骨窩で管が内側へ曲がり始める高さ（y = 0.886 m）。その下（曲がりから先）が S状結腸（`parts: ["sigmoid colon"]`）。
- 総肝管: BodyParts3D の総肝管は十二指腸まで続く。胆嚢管が合流する高さ（y = 1.081 m）から下が総胆管（`parts: ["bile duct"]`）。
- 肝臓の第IV区域: 肝門（左右の肝管が合わさる所、y = 1.103 m）より下が方形葉（`parts: ["quadrate lobe of liver"]`）。上は右葉に入れる。肝臓の語の parts にも足す。
- Z-Anatomy の形は scripts/za/index.mjs の `ZA_CUTS` で同じように分ける（骨に合わせて動かしたあとの形を切る）。咽頭口部は口腔（舌と口蓋の間の空間）まで1つの形なので、口峡のあたり（z = 0.12 m）より前を口腔（`parts: ["za:oral cavity"]`）とする。
- 大腿直筋: 膝蓋骨尖のすぐ下（y = 0.358 m）から下を膝蓋靱帯（`parts: ["patellar ligament"]`）。左右の部品を両方切るので `sided: true`（平面は右側で書き、左側は x を折り返す。下側の名前は "Right patellar ligament" のように左右を付ける）。
- 平面で切る処理は scripts/split-mesh.mjs（build-models.mjs と za/index.mjs が使う）。
- Z-Anatomy の骨・器官との合わせ込みは、切る前の形（`readWhole`）で計算する（Z-Anatomy の下行結腸は切った上側より長く、切った形では合わない）。
- 確かめるときは、上側と下側を色分けして描く（切り口がふさがっているかは、切り口の側から描いて見る）。

## Z-Anatomy の取り込み

Z-Anatomy（BodyParts3D をもとに作り直された全身モデル）は骨の形と位置が BodyParts3D と少しずつ違う（足で約8cm上、前後に約9cm、脛骨の長さも違う）。そのまま重ねると筋が骨から浮くので、骨どうしを合わせて、その「ずれ」で筋・神経・内臓を動かす（scripts/za/）。

- 読み込み（read.mjs）: three.js の FBXLoader で FBX を読む（骨格・筋・神経・内臓・循環器の5つ。循環器は CardioVascular41.fbx）。cm・Y上・前が +z なので ×0.01 でモデル座標。名前の末尾の l / r は、同じ名前の l と r がそろうときだけ左右とみなす（"Liver" の r は左右ではない）。36点ほどの形は名札の印なので使わない。
- 骨の組（warp.mjs の anchorPairs）: 同じ名前の骨を組にする（椎骨 "vertebra c5" ↔ "fifth cervical vertebra"、肋軟骨、指の骨、左右の位置などの書き方の違いを合わせる）。骨から遠い内臓のために気管・食道・胃・腎臓・脳幹なども組にする。
- 合わせ込み: 組ごとに ICP（両向きの最近点。初めは相似変換、後半はアフィン）。結果は data-raw/z-anatomy/anchors.json に覚える（合わせ方を変えたら index.mjs の VERSION を上げる）。
- 動かし方: 点ごとに、近くの骨（近いほど重い）の変換を混ぜる。6mm の格子の角だけで計算して間を補う。両方にある筋（腕橈骨筋・胸鎖乳突筋・外腹斜筋など）で、合わせたあとのずれは中央値 1〜6mm（合わせる前は 5〜10cm）。
- 切り取り（index.mjs の CLIP）: Z-Anatomy の内腹斜筋・腹横筋は腱膜まで1つの形で腹直筋の前をおおうので、前から見て腹直筋と重なる所を切り取る（`by`）。総頚動脈・内頚静脈は、BodyParts3D の同じ側の形の上端より上だけを使う（`above`。BodyParts3D の形と重ねて足す）。
- 血管は枝ごとに別の形になっている（顔面動脈の子に眼角動脈、左結腸動脈の子に上行枝・下行枝など）。語の形には、その血管の続き（終枝）だけを足し、別の名前のある枝は入れない。
- 3Dのファイル: Z-Anatomy 由来の形は系統ごとに別の GLB（`<系統>-za.<ハッシュ>.glb`、CC BY-SA 4.0）にし、アプリは同じ系統として一緒に読む（index.json の `systems.<系統>.za`）。
- 確認: `node scripts/za/check.mjs [語ID,…]` で、取り込んだ形を骨と重ねた画像を data-raw/za-check/ に描く（前・後ろ・横）。語を足したら必ず見る。

## 筋の付着面

筋の起始・停止は、骨の部位のピン（`originAt` / `insertionAt`）に加えて、Z-Anatomy の「骨の上の付着面」から作った面で示す。ピンの無い起始・停止（上腕筋の起始など）もこれで示せる。

- 作り方（scripts/za/attachments.mjs、`npm run build:attachments`）: 付着面の形（骨の子で、名前は筋の名前＋ o/e＋番号＋左右）を骨に合わせて動かし、BodyParts3D の骨の表面に寄せ、半径8mmの球の並び（1つの起始・停止で24個まで）で覆う。右側の骨の上の面だけを使う。
- Z-Anatomy の o（起始）/ e（停止）は教科書と逆のもの（斜角筋・前鋸筋など）や片方しか無いものがあるので使わない。どの骨の上の面かだけを見て、スクリプトの表（筋ごとに Z-Anatomy の名前・起始の骨・停止の骨）で振り分ける。表に無い骨の上の面は捨てる。
- 出力: public/models/attachments-za.json（`{ 筋の語ID: { origin: [[骨の語ID, x, y, z, 半径, 面の向き…], …], insertion: … } }`）。アプリは起動時に読み、`viewer.highlight` の marks に `"語ID@origin"` `"語ID@insertion"` を渡すと塗る（quiz.ts の attachMarks）。
- 1度に塗れるのは64個まで（左側への折り返しを含む）。超えるときは左側への折り返しをやめる。
- 確認: `node scripts/za/attachments.mjs --check` で data-raw/za-check/attach-*.png（4筋ずつ、前・後ろ・外・内）。筋を足したら表に足して見る。
- Z-Anatomy に付着面の無い起始・停止（烏口腕筋の停止、深指屈筋の起始、肋間筋、菱形筋・頭板状筋の起始（棘突起）、大腰筋の起始、腹直筋の起始、舌骨の停止、長腓骨筋の停止など17筋）は、骨の部位のピンと同じ規則で作る: `scripts/pins/rules/attach.mjs` の `ATTACH`（`"筋の語ID@origin|insertion"` → 規則。規則には骨の語ID `bone`、部品を絞る `part`、部品ごとに同じ規則を当てる `each` を書く）。`node scripts/pins/compute.mjs scripts/pins/rules/attach.mjs` で data-raw/pin-check/att-*.png に確認画像、`--write` で content/attachments.json（形は attachments-za.json と同じ、Claude が作ったデータ）。アプリは両方を合わせて使う（src/content.ts の loadAttachments）。
- アプリは正中から 1cm 以上離れた球だけを左側に折り返す。左右にある付着は x < -0.01 に、正中の付着（棘突起・舌骨体）は x ≈ 0 に置く。
- 骨に付かない起始・停止（手掌腱膜・白線・腱中心・皮膚）は示さない。

## 骨・器官の部位（ピン）

BodyParts3D は骨や器官を1つの形としてしか持たないので、突起・窩・稜や噴門・肺門などの「部位」は表面の位置（ピン）で示す。

- 内容: content/terms/skeletal.json の `skel-pt-` で始まるレッスン（11レッスン・170部位＋隆椎。うち21部位は Phase 3 その4 の下肢。その後、上肢・頭蓋底の追加と、Phase 3 その8 で骨学実習の手引きをもとに7レッスン・64部位を足した）。器官の部位は消化器の `dig-pt-`（胃・十二指腸・結腸・肝臓・膵臓・舌）、呼吸器の肺の部位・気管分岐部・喉頭隆起、泌尿器の `uro-pt`（腎門・膀胱・尿道）、内分泌の甲状腺の部位（43部位）。部位は `of` で骨・器官を指す。
- 位置: content/pins.json に `{ "部位の語ID": { "at": [[x, y, z], …], "r": 半径, "n": [外向き] } }`。座標はモデル座標（m・Y上・前が +z）で本人の右側（x < 0）。表示とタップの判定は左右を折り返して両側に効く。
  - `at` が1点なら結節・突起・孔など、数点なら稜・線・縫合（点の列）。孔（閉鎖孔・大後頭孔・椎孔など）は孔の中心に置き、球の範囲で縁をぐるりと示す。
  - `n` は面の外向き。その向きの面だけを塗り（肩甲骨のような薄い骨で裏まで塗らない）、カメラもその向きから寄る。外科頚・橈骨頚のように骨を一周する部位は `v`（カメラの向きだけ）にして全周を塗る。`cam` は寄るときにカメラを置く向きで、n・v より優先する（下顎骨の内面の部位は、面の向きから寄ると反対側の下顎骨にさえぎられるので、内側の下や上から寄る。規則にも `cam` を書ける）。
  - `one: true` は左右に折り返さない。胃・肝臓・膀胱など左右の無い器官の部位（幽門の反対側は胃体なので、折り返すと間違った所が正解になる）、左肺だけの部位（心切痕・小舌。x > 0 のまま置く）、左右で高さの違う部位（斜裂・腎門。左右それぞれに点を打つ）に使う。
- 表示: src/viewer.ts のスポット用材質（シェーダー）が、ピンの球の中の表面を色で塗り、縁を少し濃くする。部位を出すときは親の骨・器官だけを不透明にして周りを半透明にする。器官の部位では器官を淡い色にして（消化器の橙・泌尿器の黄の上でも橙のスポットが見えるように）、器官の形が分かるところまで引いて映す。
- 出題: 位置→名前の選択肢はピンが近い、同じ系統の部位（骨の部位に胃の部位を混ぜない）。名前→位置は骨・器官だけを見せて正面やや右から映し、ピンの範囲（半径＋6mm）に当たれば正解。外れたらタップした所を青い点で示す。
- ピン打ちツール: `?admin=1` で開くと「ピン」タブが出る（#/admin）。部位を選んで骨・器官をクリックすると位置が決まる（左側をクリックしても右側に記録。「左右に折り返さない」にするとクリックした側のまま記録し、`one` を付ける。器官の部位でまだピンが無ければ最初からこちら）。「点を足す」で稜や縫合を数点で打つ。半径はスライダー。開発サーバーでは「保存」で content/pins.json を書きかえる（vite.config.ts の pinWriter）。それ以外ではファイルとして保存する。
- 最初の149部位のピンは、骨の形から規則で計算し、骨を描いた画像で1つずつ確かめた。1か所を直すときはピン打ちツールを使う。部位をまとめて足すときは規則で作る:
  - `scripts/pins/rules/*.mjs` に部位ごとの規則を書く。規則の種類: `ext`（ある向きに最も出た点。`box` で範囲を絞る）、`ridge`（断面ごとの最も出た点の列＝稜・縁）、`groove`（輪郭の溝の底と両わきの稜）、`notch`（縁の最も引っこんだ所）、`cap`（骨頭に球を当てはめた縁＝解剖頚）、`seam`（2つの骨が接する所＝縫合）、`slices`（高さ s の断面に横から当てる）、`ray` / `rays`（確認画像の枠の中の割合で当てる。`center` で孔の縁の平均＝孔の中心）、`between` / `towards` / `nearestTo` / `near` / `fromMid`。`ring: true` は骨を一周する部位（`v` で書く）。
  - 器官の部位の規則: `one: true`（折り返さない）、`side: "left"`（左の部品で計算。左肺の心切痕など）、`union: [規則, 規則]`（左右で別の規則の点を1つのピンに。`ring: true` と一緒に使い、向き `n` はカメラ用）、`near` に座標の配列（尿道のような細い管の点の列）。規則は rules/digestive.mjs・respiratory.mjs・urogenital.mjs・endocrine.mjs。Z-Anatomy の形（肺・甲状腺）を使う語のときは、compute.mjs が Z-Anatomy も骨に合わせて読む（geometry.mjs の `loadDb({ za: true })`）。
  - `node scripts/pins/compute.mjs scripts/pins/rules/<骨>.mjs` で計算して data-raw/pin-check/ に確認画像（部位ごとに色と名前）を描く。確認画像の `side: "all"` では、アプリと同じく左側にも折り返して描く。合ったら `--write`（まだピンの無い部位だけ書く）。規則で作り直すときは `--force`（ピン打ちツールで直した分も上書きするので注意）。
  - 下見は `node scripts/pins/inspect.mjs view|hits|depth`（骨の画像、光線が当たる所の地図、奥行きの地図。`SIDE=left` で左の部品）。孔は hits で縁を探し、くぼみ（眼窩）は depth で探す。
  - 画像を目で見て座標を読むと少しずれやすい。決めたら必ず確認画像で確かめる。

図鑑のアトラス式の操作（アトラスのアプリの「隠す」「薄くする」「保存したビュー」にならった）:

- はがす: 語を選ぶと「隠す」「薄くする」。表の筋などをはがして奥の構造を見て、タップで選べるようにする（隠した部品は描かない、薄くした部品は半透明で選べない。viewer.setPeel）。骨の部位では骨ごとはがす。基本の用語・局所解剖は部品を持たないのではがせない。はがした語は欄の上に並べ、押すとその語だけ戻す・「1つ戻す」（新しいものから）・「全部戻す」。はがした語でも、一覧から選ぶと強調して見せる（「もとに戻す」が出る）。画面を離れると戻る。
- 表示の保存: 「表示を保存」で、出している系統・皮膚・はがした語・選んだ語・断面・視点（viewer.view）に名前を付けて db.settings の exploreViews に残す。一覧の先頭のフォルダー「保存した表示」から開き直す・消す。記録の書き出しにも入る。
- PC でマウスを重ねると、その部品の名前をカーソルの右下に出す（viewer.onHover。光線は 70ms ごと、外れたときに周りは探さない）。

- 公開先は https://9hckg4shj6-glitch.github.io/anatomy-app/ （GitHub リポジトリ 9hckg4shj6-glitch/anatomy-app）。`main` に push すると `.github/workflows/pages.yml` が `npm run check` を通して GitHub Pages に出す。base（`/anatomy-app/`）は vite.config.ts が GITHUB_ACTIONS のときに付ける。
- PWA（vite-plugin-pwa）。HTML・JS・CSS・`models/index.json`・`audio/index.json` は最初に保存し、GLB と音声は開いたときに保存する（CacheFirst。ファイル名にハッシュがあるので古いものは残らない）。
- 新しい版: Service Worker が入れかわったら、ホームにいれば読み直し、レッスンや復習の途中ならホームに戻ったときに読み直す（レッスンの進み具合は最後まで保存しないため）。ホーム画面のアプリは開き直しても読み込み直さないことが多いので、画面に戻るたびに新しい版を確かめる（src/main.ts）。
- 記録は端末ごと（IndexedDB）。iOS は Safari とホーム画面のアプリで記録が別なので、ホームの案内で「追加してから始める」よう勧める。レッスンを終えたときに `navigator.storage.persist()` で消されにくくする。端末をまたぐ同期は Phase 3。
- スマホの画面: 3Dを上に留め、その下で説明がスクロールする。「次へ」「前へ」は画面の下に留める（欄の最後の行だけ。途中の行を留めると3Dに重なる）。系統のボタンは1行で横にすべらせる。横向き（高さ540px以下）と PC は3Dと説明を左右に並べる。ノッチ・ホームバーの分は `env(safe-area-inset-*)` であける。
- 3Dの操作: 自分で回したり拡大したりすると、3Dの右上に「視点を戻す」が出て、アプリが最後に決めた視点（語に寄る・全身など）へ戻れる。2本目の指が触れたら（ピンチ）指を離してもタップにしない（名前→位置の誤答を防ぐ）。図鑑は語を指定せずに開くと全身から始める。
- レッスンの途中（確認テストを終えるまで）にタブなどで画面を離れようとすると確かめる（AppContext の guard）。進み具合は終わるまで保存しないため。
- PC のキーボード: 4択は数字キー（1〜4、0＝わからない。マウスのある端末では選択肢に番号を添える）、レッスンは ← → で前後、「次へ」は Enter。
- 英語のつづりの入力は、iOS の自動修正・自動の大文字を切る（autocorrect="off" など）。
- アイコン: `public/icons/icon.svg` が元。`npm run build:icons` で PNG（角丸・iOS 用の正方形・Android 用の maskable）を作る。
